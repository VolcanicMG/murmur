# murmur

Local voice dictation for Windows: hold a key, talk, and cleaned text is pasted into the active app. Parakeet (ONNX, CPU) transcribes; a bundled llama.cpp runtime cleans the text up. Nothing leaves the machine unless you enable a remote provider.

## Install
Download `murmur-windows.zip` from [Releases](../../releases), unzip it (keep the `murmur` folder together) and run `murmur\murmur.exe`. The first launch opens a short setup (microphone, cleanup model, hotkeys); there is no autostart.

The build is **not code-signed** (no certificate), so Windows SmartScreen shows "Windows protected your PC" the first time: click **More info**, then **Run anyway**. To check the download, compare `(Get-FileHash .\murmur-windows.zip -Algorithm SHA256).Hash` with `SHA256SUMS.txt` from the same release; where available, `gh attestation verify .\murmur-windows.zip --repo VolcanicMG/murmur` proves it was built by this repo's release workflow. Third-party licenses are in `THIRD_PARTY_NOTICES.md` (also shipped next to `murmur.exe`).

### Build from source
Run the installer build (`./packaging/build.sh` from WSL; see `packaging/README.md`): murmur lands in `%LOCALAPPDATA%\Programs\murmur` as a folder with `murmur.exe`, plus a Desktop shortcut `murmur.lnk`. The first launch opens a short setup (microphone, cleanup model, hotkeys); run it again any time from the tray (About > Run setup again) or `murmur --setup`. There is no autostart.

From source instead:
```
python -m venv %USERPROFILE%\.murmur\venv
%USERPROFILE%\.murmur\venv\Scripts\pip install -r requirements.txt
```

**Cleanup model.** The default provider is `builtin`: a managed llama.cpp server. Its runtime (~90 MB) is fetched on first use into `~/.murmur/runtime`, and it uses an existing LM Studio `gemma-4-e4b` GGUF if one is on the machine; otherwise Settings offers a ~6 GB model download (only when you click it). LM Studio is optional: with it installed, it is the fallback if the bundled model is down, and a config can still use it as the primary (`[llm] provider = "openai"`). The speech model is Parakeet TDT 0.6B **v2** (English-only: lower English error rate than the multilingual v3; int8 matches fp32). Takes are decoded as recorded: the usual conditioning recipe (trim/pad/pause-cap/gain, kept in `murmur/audio.py` for `evals/stt_compare.py`) made Parakeet v2 measurably worse on real takes (spelled-out numbers, dropped words). What does run: a segment with no speech energy is never decoded (Parakeet answers silence with "Yeah."/"Okay." — the source of the stray word at the end of long takes), and a take with under 0.25 s of detected speech and at most three words is treated as invented and nothing is pasted. The model (~640 MB) ships inside the build (`packaging/build.sh` fetches it once with `python -m murmur fetch-model`); a source checkout without `packaging/models/parakeet` falls back to the Hugging Face cache. Startup shows a grey loading bar on the card that fills at a steady pace over 4 s (speech model → window access → cleanup model, never jumping), turns into a green "Ready" for 1 s, then hides (the start-up card has no speech-bubble tail: it points at nothing); hotkeys work as soon as the models are up. `[stt] path` points at your own onnx-asr model folder (config.json + .onnx); Settings › Config offers it as a folder picker next to the bundled model, never as free text.

## Hotkeys
- Hold `right ctrl`: dictate. Release to paste.
- Hold `right alt`: command mode. Speak an instruction. It edits, in order: the real selection (UI Automation's answer is authoritative, even when empty; the ctrl+c fallback only runs when UIA can't say, and never in `[apps] no_copy` apps); else **your last dictation** if it is still right before the cursor (same app, within 10 min; murmur selects it and the result replaces it, so "make that more formal" or "change X to Y" edits instead of appending); else it generates new text at the cursor. The card header says which: `(selection: N chars)`, `(editing last dictation)` or `(new text)`; history rows record `target`.
- Only the side-specific key triggers (left ctrl/alt are ignored).
- **Hands-free:** tap the dictate key (released within `[dictation] tap_ms`, default 300 ms; `toggle = false` disables it) and recording latches (chip: "Listening · hands-free"). Press the key again (that press does not start a new session), Enter (insert now) or Esc (cancel) to end it, or just stop talking: after you have spoken, `silence_ms` (2000) of quiet finishes it, and `no_speech_ms` (6000) with no speech cancels ("No speech", nothing pasted). Speech is detected by the bundled **Silero VAD** (a 2 MB neural model scored every 32 ms, `murmur/vad.py`), so a quiet mic or talking right at the tap no longer looks like silence; without the model it falls back to the energy VAD. Holding the key still works exactly as before; the command key is hold-only.
- **Live editing:** while you talk, the card shows the live-cleaned text for what you have said so far (self-corrections like "0.43, actually 0.44" settle on the card) followed by the newest raw words, the last one dimmed.
- **Nothing selected:** an edit of existing text ("make this a list", "translate that") with no selection found says "Select the text first, then say it again" instead of writing new text; a reply asking you for the text is never pasted.
- **Rewording:** "make this formal / casual / friendlier" may change every word, so those edits are only checked for length (a third to three times the selection), not word overlap.
- **Command-mode guard:** an edit is only pasted if it looks like an edit of the selection: a reply about the text ("This is a list of…"), an echo of your instruction, or an output that drops most of the selection (unless you asked to shorten, summarise, translate or remove) is retried once with a stricter prompt, then refused with "Couldn't apply that edit" — your selection is left untouched.
- **Long dictation:** at a pause of 700 ms or more after 8 s of audio the segment is transcribed once and committed, so only the open segment is re-transcribed live (live clean pauses after the first commit). A recording stops itself at 10 minutes. A transcript over ~1200 characters is cleaned in sentence-group chunks, each seeing the previous chunk's tail, with the plausibility guard per chunk, then pasted once.
- While you dictate, the caption card floats above the focused field (see Overlay below).
- `ctrl+alt+m` (or History › Fix…): opens **Fix a dictation**: what murmur heard, the pasted text to edit into what you meant, and a live "Will add to your dictionary: …" preview. Save (Ctrl+Enter) teaches the dictionary and keeps the correction as an example for future dictations; it doesn't change text already pasted. Esc cancels; only one fix window opens at a time.
- `ctrl+alt+d` (`[hotkeys] learn_word`): select 1-4 words and press it to add them to the dictionary (UIA selection, clipboard fallback outside `no_copy` apps). The overlay flashes `Learned → "word"`. It fires on key press (the app logs `hotkey learn_word fired`); `trigger_on_release` never fired in the keyboard library.

### Spoken commands
Say exactly "scratch that", "undo that", "undo" or "delete that" (fillers like "um" and punctuation are ignored; extra words mean it's dictation). If murmur pasted within the last 60 s into the app that is still focused ("scratch that" only works in the app you pasted into; elsewhere it says "nothing to undo here") it sends one `ctrl+z`; otherwise it flashes "nothing to undo". Nothing is pasted or logged. "new paragraph"/"new line" are handled by the cleanup prompt.

**Scratch that mid-dictation** is applied deterministically before the LLM: each cue ("scratch that", "scratch that last one/part/bit", "delete that", "never mind that", "strike that") removes itself and the sentence before it (back to the previous . ! ? or the start; filler-only fragments are skipped). Words after the cue in the same sentence are kept as the replacement ("Tuesday, scratch that, let's do Thursday" -> "let's do Thursday."). If the whole utterance was scratched, nothing is pasted and the card says "Scratched". In command mode, exactly "scratch that" undoes the last paste; "scratch that, instead …" corrects your last dictation with the remainder.

**Voice dictionary (command mode):** with 1-4 words selected, "add this word to the dictionary" (also save/put/learn/remember this/that/it [word/term/name] to/in the/my dictionary, or "learn this word") adds the selection; "add Toung to the dictionary" adds a single spoken word. Nothing is pasted or logged.

**Capitalisation:** a sentence starts with a capital unless the text before the cursor is clearly mid-sentence (it ends in , ; : - ( [ { or a quote, or the current line is 4+ words ending in a lowercase letter and doesn't look like code). Code-looking first words (`my_var`, `--flag`, `app.py`, lone CLI commands in code tone) are left alone.

### Auto-learn
If you dictate a near-identical sentence (same app, within 90 s) that differs by 1-3 words, murmur treats it as a correction: changed names/terms go into the dictionary and the earlier history row is marked corrected, which feeds the few-shot corrections in the prompt.

## Config (`~/.murmur/`)
`config.toml` (hotkeys, llm, stt, per-app tones), `dictionary.txt` (preferred spellings), `snippets.toml` (say "insert sig"), `style.md` (generated), `history.jsonl`, `murmur.log`.

`learn` summarizes recent history into `style.md`, which is fed into the cleanup prompt.

## Customising
Tray menu > Settings… (or `.\run.ps1 --settings`) edits all of this in a window: history (Dictation/Command mode per row, a Raw vs Final pane to compare what was heard with what was typed, copy/fix/delete, time-saved stats for dictation), dictionary, snippets, prompt, tones and config (a form of toggles, dropdowns, hotkey recorders and an app-to-tone table; the raw `config.toml` sits under Advanced and keeps comments, a form save drops them). The config form saves itself: toggles and dropdowns at once, text fields when you leave them (or close the window). Config/tone saves apply live, hotkeys included.

**Single instance:** a second tray launch shows a native "murmur is already running" box and exits (named mutex `Local\murmur-single-instance`); `--settings`, `--selftest` and `learn` are unaffected.

**Sounds:** `[ui] sounds` (default true) and `[ui] sound_volume` (any value from 0 to 1 in config, default 0.25; the Settings form offers 0.1 / 0.25 / 0.5) control the soft cues (`murmur/cues.py`: start when recording begins, stop when it ends, done on paste, error on error/offline/paste failure, cancel on Esc/No speech/Scratched; generated in memory, played via `winsound`). Settings > Config > Dictation has the toggle, a volume select and a Test button.

**LLM fallback:** `[llm] fallback = true` plus an `[llm_fallback]` table (provider/url/model/api_key_env/timeout, default Anthropic Haiku) retries a failed cleanup request (connection refused, timeout, HTTP 5xx) on the second provider. After a primary failure the primary is skipped for 60 s so each dictation doesn't wait out a timeout, then retried. The fallback sends your dictated text (and cursor context, if enabled) to that provider, so the startup warning also fires when it is remote. When the fallback answered, the Pasted card reads "Pasted · fallback".

**File tags (code editors):** in VS Code, Cursor and Windsurf, a spoken file name that matches exactly one file in the open workspace becomes its relative path (`src/app.py`, or `@src/app.py` in an AI chat input); ambiguous or unknown names stay as spoken. `[code] file_tags` = `"off"` | `"chat"` (default: only when the focused control's name/class looks like a chat/composer/copilot/prompt/ask input) | `"always"`. The workspace folder comes from the window title matched against the editor's `storage.json` (WSL windows map to `\\wsl.localhost\<distro>\...`), plus any `[code] roots`. Files are listed with `git ls-files` (2 s cap, else a 5000-file walk), cached 60 s; if the index isn't ready the text is left untouched.

**Adapting to you** (`[learning]`, all off in private mode and in password fields; command rows never feed learning):
- `auto_edits`: if you hand-correct text murmur pasted (within 30 min, same app), murmur notices at your next dictation or ~45 s after the paste, learns new names/terms for the dictionary and marks the history row corrected so it feeds the corrections few-shot. Only small edits count (similar enough, at most 4 words changed, no deletions); a case-only change teaches nothing.
- `phonetic`: before cleanup, sound-alikes of dictionary terms are swapped in ("pod stead" becomes "Podstead", "get reach" becomes "gitreach"); weaker matches only appear as "Possible mishearings" hints in the prompt. A word that already equals the term is never touched.
- `style_auto` / `style_every`: `style.md` is rebuilt from recent history after `style_every` (50) dictations once there are 30 or more, in the background and never during a recording. A failure keeps the old file and retries after another `style_every`. Counters live in `~/.murmur/state.json`.
- `[context] thread` (default off) / `thread_chars` (600): reads a little of the conversation above the input (Discord, Slack...) via UI Automation as reference for spelling and tone. Only when no remote provider can be reached (primary local or `builtin`, fallback off or local), never in terminals or password fields.

**Bundled model:** new configs use `[llm] provider = "builtin"` (llama.cpp runtime managed by murmur, `[builtin]` table) with LM Studio as the fallback (`[llm] fallback = true`, `[llm_fallback]`). An existing config keeps its provider. The runtime starts at boot with one throwaway warm-up chat; Quit stops it. A dictation that arrives while it is still starting shows "Model starting...". `murmur --version` and `murmur --setup` print the version / open the setup window, which also opens once on a brand-new `~/.murmur`.

**Spoken forms (deterministic, before the LLM):** "0.43, actually 0.44" keeps only 0.44 (numbers only; word corrections stay with the LLM), a spelled number right before a unit becomes digits ("fifteen hundred milliseconds" → 1500 milliseconds; small numbers before everyday units like "three seconds" stay words), "quote Starting end quote" (also open/close quote, unquote, or just "quote" again; the marks are re-applied after cleanup if the model drops them) becomes "Starting" in quotes, "new paragraph" / "new line" become line breaks when they are commands (not "a new paragraph of text"), and spoken addresses become text: "john dot smith at example dot com" is john.smith@example.com, "double u double u double u dot example dot com slash docs" is www.example.com/docs (a known top-level domain is required).

**Speaking coach (`[coach]`):** every dictation row also records how you spoke, measured on the heard transcript and independent of the LLM: `duration_s`, `speech_s` (VAD-detected speech, when available), `pauses` (silent gaps of 700 ms or more inside speech), `fillers` (um/uh/umm/uhh/erm/hmm, plus "like" at the start of a clause or before a comma), `self_corrections` (actually / no wait / I mean / scratch that / strike that) and `words_raw`. Nothing is recorded in private mode or for password fields, and older rows without these keys are skipped. `murmur/speech.py` turns rows into trends (words per minute, fillers and corrections per 100 words, pauses, cleanup distance, sentence length) against a baseline from your first 14 days or 50 dictations; it needs 50 measured dictations before it says anything. `[coach] goals` picks what to show; `card_hint = true` adds a short note to the Pasted card ("um ×3 · 142 wpm").

**Timing:** every dictation logs `timing tail=… stt=… clean=… paste=… total=…` (key release → text in the app) to `murmur.log`, and history rows carry the same `latency` breakdown.

**Privacy:** `[privacy] history_days` (0 = keep forever) purges older history rows at startup and every 24 h. `[privacy] private = true` (tray: "Private mode") writes no history and learns nothing automatically (no re-dictation learning). Password fields are detected through UI Automation (`IsPassword`); the verdict is published first and waited for (up to 1.5 s) at release, the card shows only dots until UIA says the field is not a password, and an answer that never comes counts as sensitive: private, local-only, typed. Nothing there is read, cleaned by the LLM, shown back, logged, saved or kept for "edit last"; dictation is typed (never via the clipboard) and the card says "Typing into a password field \u00b7 not saved"; command mode refuses ("Not available in password fields").

**Encryption at rest:** `history.jsonl` (each line) and kept recordings (`.wav` + `.txt`) are encrypted with Windows DPAPI under your Windows login (`murmur/seal.py`), so a copy of the files (stolen disk, backup, another Windows account) can't be read. It does not protect against software running as you. Files from before encryption are sealed in the background at startup; `python -m murmur seal [DIR...]` does it on demand and also seals extra folders (e.g. `evals/cases/local/audio`). `murmur.log` never contains dictated text. `style.md`, `dictionary.txt` and `config.toml` are not encrypted. The eval tools that read history or recordings (`evals.build`, `evals.run` audio cases, `evals.stt_compare`) need the Windows venv; what they write (`evals/cases/local/*.jsonl` built from your history, `evals/results/`) is plaintext.

**Excluded apps and games:** `[apps] exclude = ["game.exe"]` makes every hotkey (dictate, command, learn word, fix last) do nothing, with no card or sound, while that process is in front. Two ways to set it: right-click an `.exe` or shortcut in Explorer → **Don't use murmur in this app** (on Windows 11 under "Show more options"; it runs `murmur --exclude <file>`, the running murmur picks the change up within 3 s and says so on the card; right-click again to turn it back on), or edit the Excluded apps list in Settings › Config. `[apps] shell_menu = false` (or the Config toggle, or `murmur --shell-menu off`) removes the Explorer entry; it lives in HKCU, no admin needed. `[apps] pause_fullscreen = true` (default) does the same while Windows reports a Direct3D exclusive-fullscreen app (`SHQueryUserNotificationState` = 3).

**Clipboard:** text murmur puts on the clipboard is flagged so Windows keeps it out of Win+V history and cloud clipboard; a paste (and the ctrl+c selection probe) saves and restores every clipboard format it can round-trip (text, HTML, RTF, images, file lists; GDI-handle formats and anything over 64 MB fall back to text only), so a dictation doesn't destroy something you copied.

**LM Studio discovery:** `[llm] lms` and `lms_load` default to `""` = automatic: murmur looks for `lms` in `%USERPROFILE%\.lmstudio\bin`, LM Studio's app folder, then `PATH`, and builds the load command from `[llm] model`. If LM Studio isn't found the server/model steps are skipped (logged once) and the usual offline path applies. Explicit paths in an existing config keep working.

**Hotkeys apply live:** saving a changed `[hotkeys]` table re-binds the hooks without a restart (deferred until a running recording ends).

Everything lives in `~/.murmur/`: `config.toml` (hotkeys, LLM provider, `[tones]`, `[apps]`, `[output]`, `[audio] device` (input device name, `""` = system default; pick it from the Config form, which also has a Test mic button; a missing device falls back to the default with one log line), `[audio] preroll_ms` (default 0: the mic stream is opened once and only *started* on key-down — a few ms instead of a device open, so first syllables survive, and no microphone-in-use indicator between dictations; > 0 keeps it running and includes that much audio from before the key, at the price of the indicator), `[dictation] tail_ms` (default 350: keep recording after the key comes up so the last word isn't cut), `[audio] keep_recordings` (developer tuning only: ignored unless the environment variable `MURMUR_DEV=1` is set, so an installed murmur never saves audio and Settings hides the field; default 0: save the last N takes + raw transcripts to `~/.murmur/recordings/` for `python -m evals.stt_compare`; never in private mode or password fields; Config › Dictation › **Delete all recordings** removes them), `[context]` for cursor-aware dictation; skipped for `no_copy` apps, and a warning is logged if the LLM provider is remote since field text would leave the machine), `prompt.md` (cleanup rules; only written once you change them in Settings → Prompt, so improvements to the built-in rules keep reaching you — an untouched copy of an older default is ignored), `dictionary.txt`, `snippets.toml`, `style.md`.

## Overlay (caption card)
A dark glass card appears just above the focused text field (UI Automation rect; flips below if there is no room, clamped to the monitor). It never takes focus. States: Listening, live transcript (last word dimmed), Polishing, Pasted, Command, Done, plus engine states (Loading model, Model offline, Couldn't paste, No microphone with a Retry button, Learned, Undone). While a dictation card is up, `Enter` inserts now (while polishing it pastes the raw transcript immediately) and `Esc` cancels at any point (nothing pasted or logged); both keys work even while ctrl/alt are held and are swallowed only while the card is up. Hints show only in states where they work. `.\run.cmd --demo-card [state]` previews every state. The card is a per-pixel-alpha layered window (soft shadow, real translucency, anti-aliased shapes drawn by Pillow); if Windows refuses it at startup the card falls back to a chroma-key renderer (no shadow, jagged edges). Settings pills, chips, toggles and panels use the same anti-aliased renderer (`murmur/render.py`).

## Built-in model (no LM Studio)
Set `[llm] provider = "builtin"` (or use it as `[llm_fallback]`). murmur then runs a local llama.cpp server itself: on first use it downloads the pinned runtime (Vulkan, ~33 MB zip, SHA-256 verified) to `~/.murmur/runtime` and serves a gemma-4 E4B GGUF it finds in `~/.murmur/models` or LM Studio's models folder. Options under `[builtin]`: `backend` (`vulkan` | `cuda` | `cpu`), `model`, `gpu_layers`, `ctx`, `port`. The model (~6 GB, Apache-2.0) is only downloaded when you ask for it.

## Evaluating changes
`python -m evals.run --cases core --no-llm` (deterministic scratch/fit/intent/guard cases, any OS) is the regression check for brain.py logic; `--n 3 --label X` on the Windows venv runs the LLM cases against LM Studio, and `python -m evals.compare A.json B.json` shows regressions. Cases live in `evals/cases/core.jsonl`; `evals/cases/local/` (built from your history by `python -m evals.build`) and `evals/results/` are gitignored. Details: `evals/README.md`.
